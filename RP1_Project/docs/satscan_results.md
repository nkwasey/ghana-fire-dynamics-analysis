# SaTScan cluster results and qualification

## Parsing and interpretation

Cluster results are read by their header names and checked against the selected
model. The parser preserves the source value of observed/expected separately
from the source relative-risk value. The model-specific distinction is:

| Field | Discrete Poisson | Space–time permutation |
|---|---|---|
| Observed cases | Source observed count | Source observed count |
| Expected cases | Exposure-based expectation under the configured model | Conditional expectation under the permutation model |
| Observed/expected | Source O/E | Source conditional O/E |
| Relative risk | Source `REL_RISK` | Not applicable; left missing |
| Test statistic | Source Poisson `LLR` (log likelihood ratio) | Source `TEST_STAT` |

The interpretation of each statistic depends on the configured model, inputs
and population. A Poisson relative risk compares the estimated rate inside a
cluster with the rate outside it; it must not be reconstructed from rounded
O/E. Space–time permutation expected cases and O/E are conditional
diagnostics, not exposure-based Poisson measures. Burned-pixel cases are mapped
pixel counts, not counts of independent fires. Parsing correctness does not
establish the validity of either scan model or its assumptions. See
[space_time_permutation.md](space_time_permutation.md) for the case-only
interpretation and qualification plan.

The literal p-value report is retained alongside its numeric representation,
including a leading comparison qualifier when present. A reporting threshold
that cannot unambiguously establish significance must not be used as if it
were an exact p-value. Header or model ambiguity is a validation failure.

In the publication sources, `expected` is the Poisson expectation and
`conditional_expected` is the permutation expectation. Both models use
`observed_expected_ratio`; only Poisson uses `relative_risk` and
`log_likelihood_ratio`. `test_statistic` and `test_statistic_type` preserve
the model's source statistic, and `p_value_report` preserves the source
qualifier. The run-local publication-source manifest records the validated source identities and schema. Unsupported schemas fail closed.
Use `log_likelihood_ratio` for the Poisson source `LLR`; the
parser and T3/S6 sources do not expose the ambiguous field name
`likelihood_ratio`. Generate publication sources from validated raw results.

## Validation procedure

1. Validate the parser and downstream publication contract against self-contained
   model-specific result headers and synthetic fixtures, including permuted
   columns, missing or duplicated fields, malformed rows, and qualified
   p-values. Check that Poisson RR is read from `REL_RISK`, not `ODE`, and
   that STP has no invented RR.
2. Preserve genuine raw result files and their identity when generating interpreted tables.
3. For a new scientific analysis, validate the selected geography, burned-area
   and active-fire source policies, and model/population authority. Generate new
   SaTScan parameter, case, geometry and model-appropriate exposure files.
4. Run the qualified external SaTScan executable locally, retain execution
   evidence and all input/output hashes, and validate both result families
   against the intended run. Runtime result checks do not independently prove
   that external results were generated by the recorded executable and inputs.
5. Generate fresh T3 and S6 tables and recurrence inputs from the validated
   result set. Check the actual manuscript's figure and table mapping before
   revising its statements. Preserve run identity and raw sources.

When a secondary run is selected, publication build/resume and complete-run
validation revalidate that run's raw result families and reconcile the values
of T3, S6 and F6 figure data to its run-local sources. A modified publication
table cannot pass merely by refreshing its registry hash. These checks do not
independently establish the external executable's identity or scientific model
validity. Retain execution evidence and the input, source and output hashes;
review the interpreted results against the selected raw results before using the publication tables.

Publication source manifests use a versioned
notebook-source identity based on ordered cell types, source and execution tags.
Output saves, execution counts and transient notebook metadata do not change
this identity. Scientific input, Python source, notebook source and configuration
changes remain guarded. Errors report the categories and paths that differ.
Manifest verification applies the identity scheme recorded by that manifest.
Use a fresh publication run if its recorded identity no longer verifies; do not
rewrite recorded hashes. Controlled execution records the
executed notebook as a separate hashed closeout artefact. Interactive execution
does not claim an executed-notebook snapshot or verify unsaved editor contents.

After correcting an identity mismatch, reuse an existing secondary run only if
its raw results and source identities validate. Resume with the original run
tag when the publication and closeout destinations are absent. If a failed
attempt already created a partial publication or source directory, preserve it
and use a fresh run tag and a properly prepared/validated secondary handoff;
never overwrite the partial output or manually change recorded hashes.

From the workspace root in the intended Python environment, run focused tests:

```bash
python -m pytest -q \
  RP1_Project/rp1_analysis/tests/test_satscan_header_parser.py \
  RP1_Project/rp1_analysis/tests/test_secondary_clusters.py \
  RP1_Project/rp1_analysis/tests/test_satscan_publication_fixture.py
```

These tests assess the implementation and its fixtures. They do not execute
SaTScan or certify the statistical validity of new scientific results.

## Scope

Parser checks establish field interpretation and local result-file integrity.
Scientific review additionally covers spatial and temporal support, FRP
confidence populations, MODIS observation coverage, and the assumptions of the
STP and Poisson models. Review c3 evidence states, QA/BurnDate masks, primary withholding and source
export provenance separately. Admitted scenario zeros are not proof of fire
absence; conditional supported fractions are not observation coverage. Population and model authorities must identify
their actual inputs; changed source profiles require new execution and
validation. A successful parser test does not establish that scientific results
are publication-ready.
