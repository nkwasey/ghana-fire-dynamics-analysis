# Data dependency inventory

This inventory describes the data-bearing paths distributed with RP1 Analysis
v1.1.0 and the external inputs required only for upstream reconstruction. The
normative authority rules are in `external_data_contract.md`.

## Distributed data surfaces

### `geo_data_prep/data/raw/`

Repository-owned Stage 1 source/reference geometry:

```text
aoi/gha_admin0.{cpg,dbf,prj,shp,shx}
districts/gha_admin2.{cpg,dbf,prj,shp,shx}
zones/Agro_climatic_zone.{cpg,dbf,prj,sbn,sbx,shp,shx,xml}
zones/Agro_ecological_zone.{cpg,dbf,prj,sbn,sbx,shp,shx,shp.xml}
```

These files support Stage 1 geography reconstruction and repository tests.
Generated Stage 1 runs belong under `geo_data_prep/out/<run_id>/` and are not
shipped.

### `RP1_Project/rp1_mv_firms_panels/data/`

The distributed Stage 2 data surface contains:

```text
metadata/unit_universe.csv
```

Raw yearly FIRMS files and Stage 2 boundary mirrors are not shipped. A Stage 2
rebuild supplies them locally at the paths defined by the active configuration,
including `data/raw/modis/`, `data/raw/viirs/` and `data/raw/boundaries/`.
Generated Stage 2 runs belong under `out/runs/<run_id>/` and are not shipped.

### `RP1_Project/rp1_gee_ba_scripts/`

The repository contains five Earth Engine JavaScript files and two governed CSV
export families:

```text
RP1_Project_MODIS_BA_c1_2001/   # 25 CSV files
RP1_Project_MODIS_BA_c1_2012/   # 25 CSV files
```

These files support burned-area provenance and upstream AF/BA reconstruction.
They are not executed by the canonical analysis notebook.

### `RP1_Project/rp1_analysis/data/`

This is the normal scientific input authority. It contains:

- governed ACZ and district consolidated monthly fire panels;
- merge audit/manifest material;
- ACZ and district analysis geometries;
- the district-to-ACZ maximum-overlap crosswalk and its provenance;
- exact input SHA-256 identities;
- qualified RQ1, RQ2 and RQ3 analysis/reference authorities;
- publication source authorities that do not depend on live external SaTScan
  results.

The canonical notebook and validation scripts use this repository-owned data
surface directly.

## External-only inputs

The standalone analysis does not require external acquisition. External inputs
are needed only to reconstruct upstream stages:

| Input | Acquisition/use |
| --- | --- |
| raw yearly MODIS FIRMS active-fire files | obtain from NASA FIRMS and stage for `rp1_mv_firms_panels` |
| raw yearly VIIRS FIRMS active-fire files | obtain from NASA FIRMS and stage for `rp1_mv_firms_panels` |
| Earth Engine service | required only to regenerate the shipped BA export families |
| SaTScan 10.3.3 executable | required only for genuine secondary-cluster execution and SaTScan-dependent publication products |

## Runtime-only paths

These paths are generated by execution and must not be treated as product
inputs:

```text
geo_data_prep/out/
RP1_Project/rp1_mv_firms_panels/out/
RP1_Project/rp1_analysis/out/
```

Tests that exercise these workflows create deterministic temporary or
run-scoped material and clean it after qualification.

## Dependency direction

```text
Stage 1 geography
    -> Stage 2 active-fire preparation
    -> Stage 3 AF/BA merger
    -> governed rp1_analysis/data inputs
    -> RQ1/RQ2/RQ3 analysis

Earth Engine burned-area exports
    -----------------------------> Stage 3 AF/BA merger

SaTScan 10.3.3
    <---- deterministic interface from analysis Section 04-01
    ----> validated optional results integrated by Section 04-02
```

Normal RP1 analysis begins at the governed `rp1_analysis/data` authority. The
upstream stages are reproducibility/reconstruction facilities, not mandatory
runtime dependencies of the finished analysis product.
