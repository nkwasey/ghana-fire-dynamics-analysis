# Verification

Run `python tests/run_offline.py` from this directory with Python 3 and Node.js. The suite checks deterministic builds, JavaScript syntax, the 69-field contract, synthetic scientific cases and CSV checker behavior. These tests do not submit Earth Engine tasks or establish physical-fire accuracy.

For a new replication delivery, upload the locally generated geography bundles as the three configured GEE table assets and retain the operator-declared handoff record, application/source identities and export/task identifiers where available. The pinned applications retain native-grid and source preflight checks. Admit the full requested annual delivery through the project's local c3 preparation and merger workflow, review evidence states and guarded nulls, and check expected unit-month coverage and both BA domains. Subsequent Python runs use the admitted files and receipts without recurring online asset verification. Keep generated exports, QA and model results outside this source distribution.

An admitted scenario zero does not prove physical absence of fire, and `ba_supported_fraction` is conditional on qualifying evidence rather than overall coverage. See `METHOD_AND_OUTPUT_NOTES.md` and `docs/SOURCE_REPRESENTATION_AND_SENSITIVITY.md`.

Offline tests, local admission checks and technical guards verify the source workflow. Independent checks of real rasters, remote geometry or source masks require separate evidence. The operator handoff records the declared upload and export procedure.
